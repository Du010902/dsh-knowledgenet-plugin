# @local/dsh-knowledgenet

把本地知识图谱接进 DSH：**一个节点就是一个 markdown 文件**，节点之间记「前置依赖」，
用右侧栏的「知识库图谱」面板看全局、随手补点，用 `kn_*` 工具按需读取学习节点、按纪律写。

## 它是什么 / 不是什么

- **是**：DSH 的一个插件。给**每个工作区**提供一个知识库（工作区里的 `.dsh_knowledge/`），
  以及一组让模型读写这个知识库的工具。
- **不是**：通用笔记软件，也不是把工作区变成"知识库工作区"的开关 —— 任何工作区都可以有知识库，
  有没有完全由"目录里有没有 `.dsh_knowledge/`"决定。

## 存储格式（v3，一节点 = 一个 markdown）

```
<工作区>/.dsh_knowledge/
  library.json          { formatVersion: 3, libraryId, title, createdAt, storage: "single-file-markdown" }
  Nodes/注意力机制.md      ← 一个节点 = 一个文件
  Nodes/注意力机制-2.md    ← 允许同名，自动加后缀
  graph.json            { revision, edges: [ A → B + 为什么 + 出处 ] }
```

节点文件长这样 —— 头部是元数据，**正文就是笔记本身**：

```md
---
id: 01M3NHE78B55MHMDQ9D192MXAM   ← 唯一标识（ULID）：**永不随标题或文件名变化**
title: 注意力机制
status: todo                      ← todo | learning | done
aliases: [Attention, 注意机制]
createdAt: 2026-09-29T03:00:00.000Z
updatedAt: 2026-09-29T03:05:00.000Z
rev: 2
---

这里是正文，随便写；用编辑器直接改也不会坏（front-matter 之后的都是正文）。
```

### 身份与名称彻底解耦

| 你做的事 | 结果 |
|---|---|
| 改 `title:` | 身份不变，关系不断 ✓ |
| 重命名文件（`注意力机制.md` → `Attn.md`） | 身份不变，关系不断 ✓（面板按 `id` 找） |
| 建两个同名节点 | 两个不同身份 ✓（`标题.md` / `标题-2.md`） |
| 手工丢一个没有 front-matter 的 md 进 `Nodes/` | 先给临时身份（`adopted-…`），**首次写入时固化成正式 ULID** ✓ |

### 不兼容老格式（v2）

老格式（一节点一个**文件夹** + `.meta/knowledgenet/node.json` + 每个节点一份 `relations.json`）
**已不再支持** ✓。遇到它时不给含糊结果，而是明确报错：

```
unsupported_format：这个知识库是老格式（formatVersion=2），当前版本只支持新格式…
请把 <库根> 整个删掉，然后在面板里点「知识库图谱」重新创建。
```

**迁移方式**：删掉那个目录 → 打开「知识库图谱」→ 自动建一个新的 v3 库（空库，不会动工作区其它文件）✓。

## 库 ↔ 工作区

- **任意工作区都可以有一个知识库**，位置固定为 `<工作区>/.dsh_knowledge/` ✓。
- 打开方式：右侧栏「知识库图谱」标签页（**所有工作区都可见** ✓）。第一次打开若还没有库，
  会**静默创建**一个（不弹窗、不问问题 ✓）；已经有的直接显示。
- 会话 cwd 在库的子目录里也能向上找到库 ✓。
- 也可以在工作区之外用配置固定一个库（`cordis.patch.yml` 的 `libraryRoot`）。

### 「看不到插件」是怎么做到的（隔离）

**没有知识库的工作区**：`kn_*` 工具对该会话被 `restrict` 移除、协议提示词渲染为空 ⇒
模型完全看不到插件 ✓。**有知识库的工作区**才可见 ✓，而且**建库后当前会话立刻放开**
（不用等下一个会话 ✓）。

## 工具

| 工具 | 作用 | 读写 |
|---|---|---|
| `kn_list_graph` | 默认聚焦一跳；学习时可自主选择 overview 查询全库结构，正文不随结构返回 | 只读 |
| `kn_find_node` | 按标题/别名查（判重、找复用） | 只读 |
| `kn_read_node` | 分页读目标正文、理解标记和关系计数；关系显式请求 | 只读 |
| `kn_current_node` | 查询活动视图聚焦、首轮入口或历史目标的身份与理解标记，不返回正文 | 只读 |
| `kn_enter_node` / `kn_back` | 进入前置 / 返回上一层（学习栈） | 会话内状态 |
| `kn_write_note` | 写正文（**必须带 `userConsent: true`**，且带**内容指纹冲突守卫**，绝不静默覆盖） | 写 |
| `kn_add_prerequisite` | 记一条前置（必要时建点；命中相近候选会先要你确认） | 写 |
| `kn_propose_prerequisites` | 一次提案多个前置（**只写计划文件**，不建点） | 写计划 |
| `kn_plan_status` | 查提案状态（落地了哪些、有没有失败） | 只读 |
| `kn_status` | 自诊断（路由是否注册、缓存/扫描指标、隔离判定留痕） | 只读 |

**写入纪律**（写进系统提示，模型必须遵守）：搜索类请求不得调用写入工具；建点前必须说明并等你同意；
一轮最多一次 `kn_add_prerequisite`；要一次处理多个概念只能提案，**落地只能由你在面板里点击**。

**笔记属于你本人**（写进系统提示 + 工具硬闸门）：节点正文是使用者记录自己想法的地方，
不是装解释/资料/摘要的框子 ⇒ 解释概念、回答问题、顺手"整理一下"都**不是**改笔记的理由。
模型只有在**你明确要求**、或**明确同意某个具体改动**时才写；写之前要先把"准备写什么、写进哪个节点"说清楚并等你点头。
`kn_write_note` 少了 `userConsent: true` 会被**直接拒绝**（文件一字不动），并回一句"先去问用户"。
换句话说：**它只能在你点头之后才写得进去**。

**笔记用于参考，不是标准答案**：插件要求模型把正文、标题和关系当作用户的学习记录，“已理解”也不证明记录正确。模型应核查与当前问题相关的说法，发现错误时指出具体内容、简短解释原因并给出修正；区分错误、简化表达和缺少限定条件。不确定时说明需要核实，分页未读完整时注意后续限定。纠错留在对话里，不自动改笔记、理解标记或依赖关系。`kn_read_node` 每页明确返回 `note.contentRole: user_learning_record`；这是一条回答策略和数据来源说明，不保证模型能够发现所有错误。详见 [笔记参考与纠错策略](design/note-reference-and-correction-policy.md)。

## 界面

- **右侧栏「知识库图谱」**：所有工作区可见 ✓。打开就是**整张图的三维空间视图**（默认视图），
  头部工具栏是「重新整理 / 刷新 / 搜索」。
- **进入节点群（2026-10-30 改版）**：**右键任意节点** → 菜单「进入节点群」⇒ **直接进入该节点所在的节点群视图**
  （只显示这个群的节点与关系；不弹"所有节点群供选择"的列表 ✗）。
  进群之后头行出现「返回整张图」图标按钮，点它或按 Esc 就回到整张图 ✓；
  每个群的视角按 `库身份 + 群键` 分区缓存，互不串镜头 ✓（详见 [整张图 + 节点群](design/space-node-groups.md)）。
- **建节点**：面板空白处**右键** → 菜单「创建独立节点」→ 输入名称。
  新节点**不与任何节点相连**（是独立节点，和现有独立节点同属一个群）✓（**不再有双击建点**：那是右键菜单坏掉时的临时兜底，已移除 ✓）。
- **加前置**：右键**节点** → 「添加前置节点…」→ 弹窗**只出现在图谱界面上方**；
  输入名称时，下面会列出**知识库里已有的节点**（按匹配度排序，点一下填进输入框，避免手敲出错/建重复 ✓）。
- **删依赖**：右键**连线** → 「删除这条依赖」。
- **删节点**：右键节点 → 「删除当前节点」→ 确认后**直接删掉那个 `.md`**（不可恢复 ✓）。
  节点就是一个文档，所以**没有回收站、也没有墓碑**：想留底就自己复制一份 `.md` ✓。
- **提案审阅**：agent 提交的提案会**自动弹出一个悬浮在聊天窗口上的弹窗**（agent 一交完就出现：客户端每 2 秒自己拉一次，不等图的刷新 ✓）。
  **弹窗只有两个出口**：勾选后点「创建选中的 N 条」（落地，弹窗立即消失 ✓）或点「取消这提案」（**丢弃**：弹窗立即消失、永久不再出现 ✓，并让宿主删掉计划文件 ✓；点 × / Esc / 点背景与「取消」同一语义）。
  没有「稍后再说」，面板上也没有「待审提案」这种入口 ✓ —— 待审就等于你还没决定，所以下次打开还会弹 ✓。
  落地后面板里只留一条**10 秒的短暂回执**（「已新建 N 个 · 撤销」，可点 × 立刻收起，到点自己消失 ✓ —— 不做长期占位的卡片）。
  撤销会把这批**新建**的节点删掉 ✓（落地时它们是空节点，所以不会丢内容 ✓）；回执消失后要撤掉那几个空节点，用图谱的「删除当前节点」即可。
- **节点笔记编辑器**（右键节点或选中条上的「编辑笔记」打开）：打开后以**图谱区域内的留边弹窗**显示，保留背景图谱和上方工具栏 ✓
  （3D 图谱、状态灯、视角图、提示条一起让位 ✓；点 × 关闭即原样回来、镜头不重置 ✓），
  面板够宽时正文收成一条**居中的阅读栏** ✓（一行不会拖太长 ✓）；
  标题区按面板宽度排布：宽面板一行放下节点名与文档动作；窄面板将理解 / 对话 / 关系移到第二行，给长标题留出空间。**没有模式切换**，打开就是正文（所见即所得）。
  正文比视口短时，**下面那块空白也是编辑区** ✓：点它会落到一个**末尾空段落**（已经有空段落就直接用它，不无脑加空行 ✓）
  ⇒ 在那儿**右键**同样能弹出块菜单、插表格 / 公式（不再"点了没反应"✗）。
  **正文里右键 ⇒ 弹出块菜单** ✓（标题 / 列表 / 引用 / 表格 / 公式 / 图片 / 代码块…）；**＋ 块手柄打开的是同一个菜单** ✓，

## 后台开销（桌面端流畅度）

面板只在**真的看得见**时工作 ✓：

- 面板自身可见性由 `IntersectionObserver` 判断：收起侧栏、被覆盖、零尺寸时 ⇒ **不取数、不渲染**
  （三维也不画；`requestAnimationFrame` 也不跑 ✓）；
- 三维视图**常驻挂载**（可见性只做显隐）—— 反复销毁重建会丢 WebGL 上下文 ✗
  （`panel.css` 的 `[data-visible]` 约定 ✓）；
- 切换标签页即卸载（`keepMounted: false`）✓；
- 取数有请求序号 + `AbortController`：切换工作区/刷新时旧请求被取消，过期响应不会覆盖新数据 ✓；
- 划词浮条**先判断有没有选中文字**，没有就一个请求都不发（普通点击、拖拽结束不再打扰宿主 ✓）。

## 安全边界

- 库根必须存在、且写操作**不越出库根**（路径守卫，拒绝 `..` 与绝对路径）。
- 写正文用**内容指纹**做乐观并发：外部编辑器改过就拒绝，并回传实际指纹。
- 关系写在 `graph.json`：加边**幂等**、自环与成环**拒绝**；删节点会摘掉它的边。
- 提案的落地/撤销**只有界面能触发**，agent 无法自己落地 ✓。
- 删除是**彻底删除**（无回收站、无墓碑文件）；`Backup/` 与 `.knowledgenet/` 都已随该决定移除（老库里若还留着，可以手动删掉 ✓）。
- 旧格式（v2）库不会被动过：只会报 `unsupported_format` 并告诉你怎么办 ✓。

## 图片与理解标记

笔记图片通过插件保存到知识库的 `image` 目录（可通过 `imageDir` 调整），Markdown 记录相对路径。上传上限为 12 MiB；同名上传独占创建文件并自动加后缀，避免覆盖。空图注在解析时转换为空字符串，图片可以在保存后重新打开；显示时通过插件取图接口读取，再使用临时浏览器 URL，关闭编辑器会释放这些 URL。图片节点一插入就先把 `src` 换成 1×1 透明占位（`childList` 观察器，同一个微任务里完成），避免浏览器先拿相对路径去请求 `dsh-app://app/image/…` 而刷出一条 404、并闪一下裂图；真图取回来后再换成 `blob:` URL。

仅笔记编辑器标题栏提供“已理解／未理解”按钮，立即保存到库内 `understanding.json`，不改写笔记正文。图谱默认按理解标记着色：已理解为深绿色 #167346，未理解为浅灰色 #c6cbd0；图谱工具栏、左下角和节点右键菜单均不提供理解按钮。节点状态更新保留当前布局与相机，没有标记的节点按未理解处理。普通节点的屏幕半径固定为 6px，仅选中节点放大到 6.72px；远近通过连续的透明度和柔边表达。强调连线宽 1.2px，二维箭头约 5×4.5px。

节点正文只由**人**在这里编辑；模型要写正文必须先在对话里征得同意（见上面的「笔记属于你本人」）。

图片 API 集成验证：`node --experimental-transform-types --test tests/note-images-api.integration.mjs`（需要支持该选项的 Node）。它验证同名并发上传、磁盘字节和取图接口；常规状态与图片辅助逻辑测试为 `tests/understanding.test.mjs` 和 `tests/note-images.test.mjs`；原图预览的真实浏览器端到端测试为 `tests/note-images.browser.mjs`（需要 `KN_PROJECT` 指向 DSH 依赖仓库；宿主组件用严格照契约的替身注入模块表，组件本身由宿主仓库自己的测试覆盖）。

图片编辑器样式随插件完整打包，图注与缩放控件按需显示。图片缩放高度转换为等比例宽度，让窄窗口按正文宽度收缩；保存仍使用 Markdown 的比例值与库内相对路径。正文栏最宽 860px，面板里的宽图会被缩到约 40% 甚至更小，所以点一下图片会用**宿主共享的原图预览**（`@deepseek-ai/dsh-client-ui-primitives` 的 `ImageLightbox`，聊天与文档里的图片点开用的就是它）按窗口打开原图；它自己处理 Esc、点遮罩、× 关闭与焦点还原，并且用 `--dsh-frame-chrome-top` 避开 Windows 标题栏，右上角按钮不会被窗口控制按钮压住。代价是它按窗口等比缩放且不放大超过原图，没有 1:1 缩放（3200px 的图在 1920 窗口里约 48%，仍是正文 24% 的两倍）。普通 Markdown 节点首次保存时固化正式 ID，其理解标记同时保留。

## 节点对话

笔记标题栏的“对话 N”提供创建和历史选择。关联只保存在知识库的 node-conversations.json，对话本身不记录节点绑定。**一条对话最多只出现在一个节点的历史里**：DSH 会复用工作区里的空白会话 ⇒ 同一 sessionId 可能先后从两个节点“打开新对话”，宿主按**最新一次显式认领**归属，旧节点的旧记录读取时隐藏、不改写历史文件。从节点打开对话会等待目标侧栏存储可用，再恢复来源侧栏的标签及导航参数（**属于别的会话的会话级资源标签不跟着走**：典型是 DSH 的「修改审阅」`dsh-resource://changes-review/session/<id>/…`，它的摘要在宿主内存里、重启即失，重开只会刷 404），并保留笔记弹窗与最新草稿。创建关联、第一次消息、改名和归档会主动更新历史；已知空白对话隐藏，已归档项目按左侧栏筛选显示，确定已删除的对话隐藏。详见 [节点对话说明](design/node-conversations.md)、[归属唯一修复](design/node-conversation-ownership.md) 和 [修复记录](design/node-conversation-navigation-review.md)。

## 聚焦学习与节点对话

有库不代表所有对话都是学习任务。AI 根据当前对话自行决定是否查询本工作区的知识库，不要求特定关键词或模式按钮。学习问题可以先取得节点标题、别名、关系及理解标记，再按需读取当前节点、必要的关联节点和较远节点正文。结构只作为解释背景，不要求讲解整条路线，也不自动递归读取全部前置。已理解是用户自评；没有标记不代表完全不懂。必要的陌生基础先用直观语言解释，再回到当前疑问。

笔记标题栏“对话 N”只提供“打开新对话”和历史选择。打开时记录节点到对话的单向历史，不生成草稿、不附带正文、不自动发送消息。插件为首次请求提供一个临时入口线索，指导 AI 查询聚焦及结构；首轮结束或进入下一轮即失效，重新打开历史不产生入口线索。同一会话被另一个节点重新认领时，入口线索改指向**最新认领**的节点。它不写入 DSH 会话绑定字段，插件重启后不恢复此临时线索。

`kn_current_node` 默认依次查询活动界面中的笔记/实际图谱选择、首轮入口线索和此前学习目标；`source: history` 专门追问此前目标。自动布局指定的节点不作为实际选择。界面聚焦按会话、库根和视图实例同步；正常关闭/隐藏时清理，异常断连后租约到期清理。`kn_read_node` 的 `role: background` 用于补充材料，不替换历史学习目标；默认 `role: target` 保持旧调用兼容。

聚焦有效性观察整个插件面板，不依赖图谱标题栏或键盘焦点。切到聊天输入框、开发者工具或其他窗口，仍可见的笔记继续作为当前节点；隐藏、卸载或页面离开才撤销。宿主可通过会话持久元数据确认尚未装载会话的工作区，不读取聊天内容；**三条来源都拿不到该会话工作区时以面板报的库为准**（面板报的根必须先解析成真实知识库，聚焦仍只作用于该会话自身；会话库能解析、且确实是另一个库时依旧拒收）。聚焦上报失败记录在 `kn_status` 的 `clientDiag` 中，区域为 `view-focus`（**拒收时把两个库根一起写进原因**，一眼看出是"写法不同"还是"串库"）。**归属校验比较解析后的库根**（工作区路径与 `…/.dsh_knowledge` 两种写法都认）；精确查不到时按**会话内最近活跃的视图**回落、并用**那个视图自己的库根**去找节点 ⇒ 不再出现"面板里开着笔记却说没有当前节点"。无可靠当前节点时不能把库根或总览第一项当作用户当前节点。详见 [当前笔记识别修复](design/current-note-focus-repair.md)。

全库结构默认每页最多 200 个节点、400 条关系、24,000 个 JSON 字符，分别通过 `structureMaxNodes`、`structureMaxEdges`、`structureMaxChars` 配置；局部图仍使用 `modelMaxNodes`/`modelMaxEdges`。节点和关系独立分页，完成的一侧用对应总数作为偏移，续页传回 `revision`，结构变化时从零重查。笔记长度预算不变。聚焦租约 `focusLeaseMs` 默认 45,000 毫秒，最小 3,000 毫秒，客户端按宿主返回值每三分之一租约续期。

实现与验证见 [结构上下文及聚焦学习优化](design/knowledge-structure-learning-implementation.md)，此前实现见 [聚焦学习实现记录](design/focused-learning-implementation.md)。配置默认值在插件中解析，不修改 DSH 本体、会话格式、普通工具或全局配置。DSH 原有文件工具仍可读取文件，因此这些策略不能保证模型绝不通过其他工具扫描知识库。
